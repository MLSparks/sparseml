Agents that finish the job, and prove it.

sparkrun is a lean runtime for AI agents on small models. It checks results independently, survives crashes, never repeats a side effect, and only calls a bigger model when a small one fails.

Install

One package, nothing else to run.

Python 3.10 or newer. The package installs as agentsparks-sparkrun and imports as sparkrun.

# from GitHub
pip install "agentsparks-sparkrun @ git+https://github.com/MLSparks/sparseml#subdirectory=sparkrun"

# optional: a free local small model
ollama pull qwen2.5:3b

  1. Wrap your tools

    Mark anything that changes the world with side_effect=True. It will run at most once per task.

  2. Say how success is checked

    Tests that pass, a file that exists, an endpoint that answers. The model's word never counts.

  3. List models cheapest first

    Most steps run on a free local model. A stronger one is called only when the small one fails.

Usage

A verified run in a few lines.

from sparkrun import Agent, OpenAICompatible, Policy, tool, verify

@tool(side_effect=True)                 # changes the world, so it runs at most once
def write_file(path: str, content: str):
    """Create or overwrite a file."""
    open(path, "w").write(content)
    return "ok"

small = OpenAICompatible("http://localhost:11434/v1", "qwen2.5:3b")         # free, local
strong = OpenAICompatible("https://api.example.com/v1", "big-model",          # only if needed
                          api_key_env="EXAMPLE_API_KEY", usd_per_mtok_in=1.0, usd_per_mtok_out=4.0)

agent = Agent([small, strong], [write_file],
              checks=[verify.command("pytest -q", cwd="project")],        # proof, not opinion
              policy=Policy(max_steps=40, max_cost_usd=0.50))
result = agent.run("Make the failing test in project/ pass")
print(result.status, result.cost_usd)          # "verified" only when the checks pass
Guarantees

Every way long runs break, and what sparkrun does about it.

Each guarantee is covered by the test suite, which runs on Python 3.10 to 3.13 on every change.

FailureWhat sparkrun does
Claims success incorrectlyverify.pyOnly independent checks can mark a run verified. Failed checks come back to the model as "must fix" items.
Repeats an actionrunner.pySide-effect tools get an idempotency key. A repeat returns the recorded result instead of running again.
Process crashesjournal.pyEvery change is journaled and fsynced. run(run_id=...) rebuilds the run and continues without re-paying for finished steps.
Crash during a side effectrunner.pyIt can't know whether the action happened, so the run pauses as needs_reconcile until a person approves a retry.
Gets stuck in a looprunner.pyThe same call repeated in a short window escalates to a stronger model, then stops as stuck.
Context too long or trimmedmemory.pyEach call sends goal, must-fix items, remembered facts and the newest steps. The prompt stays under a fixed size however long the run.
Messy output from small modelsrunner.pyAccepts prose, code fences, single quotes and renamed keys, and tells the model what was wrong otherwise.
Risky actionstools.pyneeds_approval=True pauses until a person approves. Tool allowlists and step, cost and time budgets are hard limits.
Cost tracked per token, not per outcomereport.pysparkrun report shows success rate and cost per verified task.
Lean by design

Built for small models and $0 infrastructure.

Small model first

Pass models cheapest to strongest. Escalation happens only after invalid replies, a failed check or a loop.

Flat prompt size

Compact task memory replaces the growing transcript, so 4k-context models stay on track and cost per step stays constant.

No servers

The journal is a JSON-lines file. No database, queue or service. It runs on a laptop, a free CI runner or a container.

~0.1 ms per step

sparkrun's own overhead per step. Only critical events are forced to disk, so safety costs almost nothing.

Parallel runs

run_many(goals, workers=64) ran 64 tasks with 50 ms model calls in 0.2 s instead of 9.8 s.

Prefix-cache friendly

The system prompt never changes between calls, so local servers can reuse its cached computation.

Limits

What it doesn't do

  • Verification is only as strong as your checks. With none, a run ends unverified, never verified.
  • "At most once" covers side effects that go through sparkrun tools. Give outside systems an idempotency key too where they support one.
  • Setup learning is a simple epsilon-greedy choice, not a full experiment framework.
